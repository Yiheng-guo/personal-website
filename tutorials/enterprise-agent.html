企业 Agent：从业务访谈到上线验收

从奎达的非工作时段咨询场景出发，练习把模糊诉求落成可交付的产品。

1. 先确定服务目标2. 区分三类回答路径3. 搭建并走通咨询链路4. 用相同任务验证优化5. 练习：写一张交付任务卡

1. 先确定服务目标

企业说“想要一个 24 小时客服”，还没有说明服务到底替谁完成哪件事。奎达的需求是承接非工作时间咨询、沉淀业务知识，再将专业问题引导给造价师。先用实际咨询问题理解需求，再决定功能。

我的判断是：先做好业务介绍、基础咨询与联系方式引导。材料价格提供近期公开报价的参考区间；个性化工程报价仍由专业人员处理。

  • 访谈负责人：客户通常问什么？哪些问题需要查资料？哪些必须由专业人员回答？
  • 梳理资料：业务范围、联系方式、案例、常见问题，标明来源和适用范围。
  • 检查入口：企业是否已有官网或其他客户入口？奎达没有官网，因此官网与咨询入口一起交付。

2. 区分三类回答路径

问题处理路径产品边界
企业业务与联系方式企业资料检索 / RAG以可核实的企业资料为依据，不编造业务和案例
近期材料公开报价Bocha Search 联网检索确认地区、规格、时间和来源，提供参考区间
个性化工程报价、资料不足说明限制并引导电话咨询不代替造价师作专业判断

RAG 是检索增强生成：先从资料中找相关片段，再让模型结合这些证据作答。联网检索补充公开信息，两者来源不同。不要把搜索到的单个报价称为市场平均价。

3. 搭建并走通咨询链路

  1. 在 Dify 中配置模型、企业资料检索和联网工具，先分别验证每一项能够返回结果。
  2. 把服务边界、资料使用原则和电话引导写入系统指令，避免要求模型无条件回答。
  3. 接入官网咨询入口，让客户能够找到客服、发起提问、看到回答，并获得联系方式。
  4. 实测超时、空结果、缺资料和连续追问。出错时给明确提示，允许重试或联系人工。
  5. 交付知识库维护方式：资料负责人、更新频率、过期资料处理和修改后的回归检查。

“转人工”在这里是提供电话并引导客户联系专业人员。没有坐席系统时，不应描述成自动接通人工客服。

4. 用相同任务验证优化

先保留一组测试问题，再调整 Prompt。记录资料是否被正确使用、边界是否守住、电话引导是否自然，同时看耗时和输入 Token。减少文字后要重新跑相同问题，确认没有删掉关键规则。

奎达同类测试问题下，系统提示词长度降低 17.7%，总输入 Token 降低 19.8%。这说明该测试口径下输入减少，不等同于回答速度提升，也不能直接推出企业整体成本降低相同比例。

5. 练习：写一张交付任务卡

服务对象：非工作时间咨询的潜在客户
核心任务：了解业务，获得基础信息，并联系专业人员
首期交付：官网入口、业务问答、联网参考信息、电话引导
专业边界：不输出个性化工程报价，不保证公开报价适用于具体项目
验收问题：业务范围 / 材料价格缺地区 / 无资料 / 专业报价 / 工具失败
验收记录：输入、返回内容、资料来源、失败原因、处理动作
维护安排：资料由谁更新，联系方式变化后如何检查
商业验证：是否真正承接咨询、是否产生有效联系，另行记录

练习时先用一组模拟资料跑通主流程，再接企业资料。可运行原型和真实客户价值要分别验证。
